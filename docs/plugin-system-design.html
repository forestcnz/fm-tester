Design Specification · 设计规格

插件系统
Inkwell Plugin Platform

一个语言无关的 CLI 插件平台——任意可执行程序都可为 FM Tester 增加新命令、新视图、新工具，与 API 测试无直接关系亦可。中心原语是命令与视图，UI 自主度覆盖声明式渲染到嵌入式 Webview。

CLI 进程 任意语言 协议 FMPP stdio·NDJSON·JSON-RPC UI 声明式 + 嵌入 Webview 隔离 沙箱 + 权限 + 审计
01
Overview

概述与定位

FM Tester 已有强内置扩展——rquickjs 脚本引擎、导入器、AI 助手、压测断言——但所有扩展点在编译期固定，第三方无法不改源码地增强。本方案建立一个通用扩展平台：一个插件可以是完全独立的工具（JSON 树浏览器、本地看板、内部运维小工具、笔记管理器），它只是「住在 FM Tester 这个壳里」，借用宿主的窗口、标签页、侧边栏、变量、凭据与日志。

§

关键演进（相对 v1）：插件不再围绕 API 测试既有功能。中心原语是 命令(Commands) 与 视图(Views)；既有「请求钩子 / 导入器 / 渲染器 / 断言」降级为可选能力组，插件按需 opt-in。i18n 中已预留 menu.plugin = "插件" 占位，本方案将其落地。

设计目标

G1

语言无关

any language

插件是可执行 CLI 程序，应用经子进程 + stdio 协议加载。Node / Python / Go / Rust / Shell / 二进制皆可。

G2

通用扩展

not bound to API testing

以命令与视图为中心；插件可提供与 API 测试完全无关的全新能力。

G3

三档 UI

declarative → webview

声明式 JSON-UI、富文本 Markdown/HTML、嵌入式 Webview（最强，类 VS Code）。

G4 声明式 manifest G5 沙箱 + 权限 G6 零侵入核心 G7 可选复用既有扩展点

与脚本引擎的关系

维度rquickjs 脚本CLI 插件
运行位置应用进程内，QuickJS 沙箱独立 OS 进程 + 可选沙箱 Webview
语言仅 JavaScript任意语言（前端可用任意 Web 技术）
能力受限 fm.* API声明任意权限 + 自带 UI
定位请求内轻逻辑跨请求 / 强能力 / 可分发 / 独立小工具

二者并存互补：脚本用于请求内轻逻辑，插件用于通用扩展。

02
Core Concepts

核心概念

一个插件即一个目录，包含声明文件、CLI 入口、可选的 Webview 前端与私有数据空间。

plugins/com.example.json-explorer/tree
plugins/
└── com.example.json-explorer/
    ├── plugin.json            # 声明文件（必需）
    ├── backend(.exe)          # CLI 入口（任意语言/二进制/脚本）
    ├── webview/               # 可选：自定义 Webview 前端
    │   ├── index.html
    │   └── app.js
    └── .fm/                   # 运行期私有数据（fs.write 默认作用域）

中心原语 Command View

⌘

命令 Command

one-shot action

一次性动作，出现在命令面板 / 菜单 / 右键 / 侧边栏入口。可带输入 schema，输出可为声明式 / 富文本 / 打开 Webview。无状态、即用即走。

▦

视图 View

persistent surface

持久 UI 面，挂载到侧边栏或主区标签页。由插件渲染（声明式 JSON-UI 流，或嵌入式 Webview），可与其 CLI 后端双向交互、保持状态。这是 VS Code「Webview View」与 Raycast「Command」的结合。

能力组 Capability Group

插件按需声明提供或接入的能力。通用能力（命令 / 视图 / Webview）为中心；既有功能位为可选 opt-in。

commands[] 通用 views[] 通用 webview 通用
hooks 请求钩子·可选 importers / exporters·可选 responseRenderers·可选 assertions·可选 tools (AI·MCP)·可选

未声明的能力即使插件实现也不会被调用（manifest 与运行期 initialize 取交集）。

03
Rendering Models

三种呈现模型

插件命令 / 视图的渲染分三档，由插件按场景选择——简单走声明式，复杂上 Webview，共用同一套协议与权限。

①

声明式 JSON-UI

light · safe

插件返回一棵组件树（JSON），应用用原生组件渲染。组件白名单：column / table / chart(echarts) / button / input … 交互经 view/action 回调。无任意 HTML 执行，最安全。

②

富文本

markdown / html

插件返回 Markdown 或 HTML，应用用既有 marked + dompurify 渲染。适合文档、报告、富结果展示。

③

嵌入式 Webview

full custom UI

插件自带 webview/index.html（任意 Web 技术），加载进沙箱 iframe，经 FMPP 与其 CLI 后端双向通信。复杂表单、看板、可视化工具，甚至与 API 测试无关的小应用。

声明式 JSON-UI 样例json
{
  "type": "column", "children": [
    { "type": "heading", "level": 2, "text": "导入结果" },
    { "type": "stat", "label": "成功", "value": "12", "tone": "success" },
    { "type": "table", "columns": ["名称","状态"], "rows": [["a","ok"]] },
    { "type": "chart", "option": { /* echarts option */ } },
    { "type": "button", "label": "重试", "action": "retry" }
  ]
}
04
Embedded Webview

嵌入式 Webview 架构

插件自带 HTML 页加载进沙箱 iframe，与其 CLI 后端经协议双向通信。这是最强呈现模型，也是安全面最大处——故隔离是第一要务。

沙箱与隔离 sandbox

  • iframe sandbox 不含 allow-same-origin → 插件页为 opaque 源，无法访问主窗口 DOM / Tauri 原生对象。
  • CSP 由应用钳制（插件只能更严）：default-src 'none'; connect-src 'none'——禁止插件页直连网络，数据一律走协议。
  • 主窗口 ↔ iframe 仅靠 postMessage，消息带来源校验。第三方资源需离线随包分发，不得外链 CDN。

Webview 的「后端」就是插件 CLI 进程；CLI 通过 fm/* 反向能力访问宿主（变量 / 凭据 / 网络 / 剪贴板），全部经权限校验。

05
FMPP Protocol

FMPP 通信协议

FMPP = FM Plugin Protocol。传输采用子进程 stdin/stdout 的 NDJSON（每行一 JSON 对象），信封为 JSON-RPC 2.0。stderr 仅用于诊断日志。生命周期为长驻进程 + 空闲回收 + 崩溃重启。

¶

选型理由：NDJSON + JSON-RPC 是 MCP / LSP / Docker / kubectl 等成熟工具链的通用做法——逐行解析无歧义、流式友好、语言无关。长驻进程摊薄启动成本；轻量场景可退化为 cli-once（调用即启动、完成即退出）。

06
Lifecycle

生命周期与策略

⤓

安装

install

来源：本地 / zip / URL（可选 checksum）。解压 → 校验 manifest（id/semver/权限白名单/入口/CSP 基线）→ 权限审查授权 → 落盘 + 登记 registry。

⟳

启停 / 升级

enable · upgrade

启停改 enabled；禁用优雅 shutdown 进程并卸载 Webview。升级新版本并存、切换指针；新增权限触发差量重新授权。

⊘

进程管理

runner

每启用插件最多 1 长驻进程，按需懒启动；空闲回收；崩溃指数退避重启；连续失败阈值 → 自动禁用并通知。

失败策略 onError

策略语义适用
continue出错/超时记日志，继续后续链默认；渲染/断言/普通钩子
abort失败即终止请求并在控制台报错强校验插件（如签名必选）
warn仅告警不记为错误非关键副作用

执行顺序（仅可选钩子链）

脚本链 + 插件钩子统一编排
前置链:  工作区脚本 → 环境 → 父集合 → 子集合 → 接口脚本
         → 插件 beforeRequest（按 priority 升序，默认 id 字母序）
              [ 网络发送 ]
后置链:  插件 afterResponse（反向）→ 接口脚本 → … → 工作区脚本（反向）

!

诚实声明：CLI 子进程在 OS 层不受权限硬约束（恶意插件理论上可直访文件/网络）。本模型实现「声明可见 + 安装授权 + 应用能力网关化 + Webview 沙箱 + 行为可观测」；所有 fm/* 反向调用与 Webview 宿主访问写入插件审计日志。OS 级硬沙箱列入路线图 P6。

Roadmap

分阶段路线图

P0
骨架

协议 / manifest / 安装 / 启停 + 设置面板 + 审计。能装、能启停、能看日志。

命令 + 声明式 UI

commands（含 cli-once）+ JSON-UI / Markdown / HTML 渲染。命令面板 / 菜单 / 右键触发，返回声明式结果。

P2
嵌入式 Webview

webview + asset 协议 + 沙箱 iframe + 消息桥。插件自带 HTML 页，沙箱内交互。

P3
常驻视图

views（侧边栏 / 主区标签页）+ PluginViewHost。插件常驻工作面。

P4
可选能力组

hooks / importers / exporters / renderers / assertions。复用 API 测试扩展点。

P5
AI 工具

tools（MCP 风格）接入 ai_tool_service，插件能力供 AI 调用。

P6
安全增强

签名校验、OS 级硬沙箱调研。提升信任与隔离。

P7
市场（可选）

在线 manifest 索引 + 一键安装。插件发现与分发。

manifest 是插件与应用之间的契约。命令 + Webview 视图（最全演示）：

Acceptance

验收标准（P0–P3）

  • plugin.json 安装校验：非法 id / 版本 / 权限 / 入口 / CSP → 明确报错
  • 长驻进程：握手 → 调用 → 空闲回收 → 崩溃重启 → 连续失败自禁用
  • 设置面板：列表 / 启停 / 卸载 / 权限回收 / 审计日志
  • 命令在命令面板 / 菜单 / 右键正确出现；JSON-UI / Markdown 正确渲染，button 回调生效
  • 嵌入式 Webview：沙箱 iframe 加载、CSP 锁定、postMessage 双向、宿主能力经权限校验
  • views 可挂载侧边栏 / 主区标签页，常驻且可交互
  • zh-CN / en 双语完整；npm run lint + cargo clippy -D warnings + cargo test 通过
