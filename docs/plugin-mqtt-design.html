MQTT Tester
嵌入式 MQTT 工作台

一个加载进 FM Tester 的 MQTT 测试插件：连接任意 Broker，订阅主题、发布消息、实时查看消息流与统计。连接驻留在 CLI 后端，与 UI 解耦——消息持续流动，即便视图被关闭。本设计同时是「如何用插件平台规范一个真实插件」的参考样板。

视图 Webview 工作台 连接 CLI 后端持有 凭据 fm.secret · AES-GCM 协议 MQTT v3.1.1 / v5
01
Overview

定位与能力

MQTT 是物联网领域的主流发布/订阅协议。本插件把它做成 FM Tester 里的一个常驻工作台——适合 IoT 调试、设备联调、消息流验证。它不依赖 HTTP 请求/响应，因此不走既有「请求钩子」，而是以 Webview 视图 为中心，辅以少量命令。

§

为何是插件而非内置：MQTT 是长连接、异步推送、二进制负载密集的场景，与 FM Tester 的 HTTP 核心正交。作为 CLI 插件，可用任意成熟 MQTT 库（Node mqtt.js / Python paho / Go paho / Rust rumqttc），不污染核心，且连接进程独立——崩溃不影响主应用。

02
Architecture

架构：连接驻留后端

关键设计：MQTT 连接由插件 CLI 进程持有，而非 Webview。Webview 仅负责渲染与交互，经 FMPP 驱动后端；后端维持长连接，把收到的消息以事件流推回 Webview。

解耦带来的三个好处：① 视图关闭/切换时连接不断，消息持续累积于后端缓冲；② 同一连接可被多个视图订阅展示（如一个看原文、一个看聚合）；③ Webview 崩溃不丢连接，重开即恢复。

04
Connection Lifecycle

连接生命周期

长连接与插件平台的「空闲回收」机制存在张力——必须让活跃连接保活进程，否则 idle 超时会杀掉连接。

①

连接保活进程

hold-alive

只要存在活跃 MQTT 连接，PluginRunner 视作「有活动」，不触发空闲回收。建议 manifest idleTimeoutMs: 0 或由 runner 识别连接态。

②

视图无关持久

view-decoupled

关闭视图/标签页不断开连接；后端继续收消息并缓冲。重开视图即拉取缓冲恢复展示。

③

断线重连

auto-reconnect

网络抖动时后端按指数退避自动重连，重订阅原 filters，并 onDisconnect/onConnect 通知 UI 更新状态点。

!

平台交互要点：插件禁用 / 应用退出时，后端须优雅断开（发 DISCONNECT，v5 携带 reason），而非直接杀进程——否则 Broker 侧会触发 LWT（遗嘱）。退出流程由宿主 shutdown 驱动。

消息缓冲与限流

  • 高吞吐 Broker 下，onMessage 通知可能淹没 Webview。后端按时间窗/数量聚合后批量推送（如每 50ms 或满 64 条一帧）。
  • 后端维护有界环形缓冲（如最近 5000 条），供视图重开时回放；超出按 topic 优先级丢弃。
  • 用户可在 UI 设「暂停接收」/「仅保留匹配过滤」以降噪。

06
Payload

负载处理

MQTT 负载常为二进制（protobuf / 自定义协议 / 传感器裸数据）。协议层一律以 base64 传输，保证二进制安全；Webview 按所选模式解码展示。

模式解码适用
UTF-8原文文本/JSON 仪表上报
JSONpretty 格式化结构化设备数据
Hex十六进制 dump（带偏移）私有协议 / 裸字节
Base64原文图片/文件载荷
§

与大负载：单条超大消息（如固件 OTA 分片）经 base64 会有 ~33% 膨胀。约定单帧上限（如 256KB），超出由后端分片推送并在 UI 标记「truncated」；亦可勾选「大负载仅存引用不渲染」。

07
Security

安全

凭据：复用宿主 AES-GCM 加密存储

Broker 的用户名/密码不存插件目录，而是经 fm/secret.get 存取于宿主的加密存储（复用既有 encryption.rs）。连接时声明 secretRef，后端凭权限取回明文用于握手。

凭据键约定secret
// manifest 声明可读的凭据键前缀
"secrets": ["mqtt.broker.*"]

// 连接时引用（不传明文）
{ "secretRef": "mqtt.broker.prod-emqx" }
  → fm/secret.get("mqtt.broker.prod-emqx")
  → { username, password }   // AES-GCM 解密后仅在握手期间驻留内存

TLS

  • mqtts:// / wss:// 启用 TLS；支持自定义 CA 证书、客户端证书 + 私钥（mTLS）。
  • 证书文件可来自插件沙箱目录或用户指定路径；insecure 选项（跳过校验）默认关闭并醒目提示。
!

网络诚实声明：MQTT 是 Broker 间的原始 TCP/TLS socket 连接，不经宿主 HTTP 网关（fm/request.send）。因此 network.outbound 权限在此为声明 + 审计性质——插件 CLI 进程直连 Broker；真正的 socket 级管控需 OS 沙箱（平台 P6）。安装授权时须向用户明示「该插件将直连你配置的 Broker 地址」。

08
Backend

后端实现选项

CLI 后端可用任意语言。权衡成熟度、分发体积与跨平台一致性：

方案库优点权衡
Node 推荐起手mqtt.js生态成熟，mqtt/mqtts/ws/wss 与 v3/v5 全支持，前端同栈需随包 Node 运行时（或 pkg 打包）
Rust 推荐分发rumqttc单二进制、跨平台一致、性能/内存佳v5 支持需确认完整性
Gopaho.golang单二进制、v5 一等支持二进制体积偏大
Pythonpaho-mqtt原型快、易写需 Python 环境，分发不便

建议：开发期用 Node mqtt.js 快速迭代，正式分发用 Rust/Go 单二进制，manifest 的跨平台 entry.command 分别指向各平台产物。

09
Roadmap

插件路线图

P1
单连接 · 基础收发

连接 / 订阅 / 发布，text + JSON 负载，实时消息流，连接状态点。够用的小型联调。

P2
多连接 · 安全 · 二进制

多 Broker 并行；TLS + mTLS；凭据经 fm.secret；Hex/Base64 负载；暂停/过滤；统计。

P3
持久化 · 场景

连接/订阅 profile 持久化；消息日志保存与回放；脚本化发布序列（编排式压测）；主题聚合视图。

P4
MQTT v5 · AI 工具

user properties / content type / topic alias / 共享订阅($share) / reason codes；mqttInspect AI 工具。
